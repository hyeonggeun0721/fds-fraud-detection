## 2-2단계 1차 실행: LightGBM 점수 폭주 (`scripts/04_tree_model.py`, 2026-11-04)

- 사용자 예상: LightGBM이 0.1 높고 5조각 중 3번 우세 → 실제: 평균 0.16 낮고 1번만 우세
- 원인 진단(클라우드): LightGBM 원시 점수(log-odds)가 최대 약 25,000까지 폭주 → 확률이 정확히 0 또는 1로 뭉개짐(전체의 11%가 정확히 0, 일부 정상 거래가 1.0, 일부 사기가 1e-23). 순위 정보가 사라져 PR-AUC 붕괴
  - 메커니즘: 잎 값 = −(기울기 합)/(헤시안 합 + reg_lambda). 이미 확률 ≈0으로 예측된 정상 거래만 모인 잎은 헤시안 p(1−p) ≈ 0 → 아주 작은 수로 나눠 잎 값이 폭발. 기본값 min_child_weight=0.001, reg_lambda=0이라 이런 잎이 허용됨
  - 증거: 같은 코드인데 조각 2 결과가 맥 0.276 / 클라우드 0.325로 다름 → 수치가 불안정할 때 나타나는 현상
- 진단 실험(클라우드, 참고용): min_child_weight=1 → 조각별 0.843~0.870, 평균 0.850, 원시 점수 최대 16 / reg_lambda=1 → 평균 0.839 / 둘 다 → 평균 0.847
- 결정(2026-11-04): **min_child_weight=1만 추가**(바꾸는 것 하나 → 원인·효과가 가장 분명). 1차 결과 파일은 `tree_model_results_v1_exploded.json`, `oof_scores_2-2_v1_exploded.npz`로 이름 바꿔 보존

|---|---|---|---|---|---|---|

- 사용자 예상: PR-AUC 최고 = 언더샘플링 → 실제로는 정상적으로 동작한 방법 중 가장 낮음 / 오경보 최다 = SMOTE → 실제로는 셋 중 가장 적음(오경보 최다는 정상 동작 중 언더샘플링, 전체로는 점수가 폭주한 클래스 가중치)
- **클래스 가중치는 점수 폭주로 무효**: 정상 거래 점수 중앙값 2e-29, 원시 점수 최대 약 3,000. 사기 1건이 600배로 계산돼 min_child_weight=1 보호막이 쉽게 뚫림
  - 클라우드 진단(참고): 가중치600+reg_lambda=1 → 0.207(더 나쁨) / 가중치600+min_child_weight=10 → 0.720(조각 하나 0.424) / 가중치 √600≈24 → **0.823**(안정, 원시 점수 최대 35) — 안정화해도 '처리 없음'(0.850)보다 낮음
- 언더샘플링: 정상 거래의 98%를 버려 '정상이 어떻게 생겼는지' 정보가 줄어 순위 능력 하락. 대신 학습이 10배 빠름
- SMOTE: 순위 능력은 '처리 없음'과 사실상 같음(차이 +0.002가 흔들림 0.007보다 작음). 가짜 사기 2만여 건을 만들어도 이득 없음
- 핵심: 불균형 처리는 순위(PR-AUC)를 올리기보다 **점수 크기를 위로 옮김**(재현율 80% 기준점: 처리 없음 0.34 / SMOTE 0.93 / 언더샘플링 0.98). 같은 모델도 기준점 0.5로 자르면 오경보가 수십 배 달라짐 → 기준점은 2-4에서 따로 정해야 함
- 결정(2026-11-04): **채택 = 처리 없음** (SMOTE와 성능 같음, 더 단순·빠르고 가짜 데이터 없음). 클래스 가중치는 (a) 재실행 없이 '가중치 600은 점수 폭주로 무효, √600≈24로 안정화해도 처리 없음보다 낮음(클라우드 진단 0.823)'으로 기록만 함

## 2-4단계 결과: 기준점 정하기 (`scripts/06_threshold.py`, 그림 `10_threshold_by_fold.png`)

기준점은 학습 조각의 안쪽 4겹 교차검증 점수로만 고르고, 테스트 조각에 그대로 적용.

| 정책 | 고른 기준점 (5조각) | 테스트 재현율 평균 | 테스트 오경보/1만 건 평균 | 목표 지킨 조각 | 5조각 합계 (잡음 / 놓침 / 오경보) |
|---|---|---|---|---|---|
| 고정 0.5 | 0.50 | 0.784 | 0.56 | – | 371 / 102 / 16 |
| 재현율 80% 목표 | 0.30 / 0.35 / 0.51 / 0.34 / 0.43 (평균 0.39) | **0.797** | 0.71 | 재현율 ≥ 80%: **3/5** | **377** / 96 / 20 |
| 오경보 예산(0.5건/1만 건) | 0.54 / 0.65 / 0.87 / 0.69 / 0.76 (평균 0.70) | 0.761 | **0.53** | 오경보 ≤ 0.5: **3/5** | 360 / 113 / **15** |

- 사용자 예상: 재현율 목표가 5/5 지켜진다 → 실제 3/5 / 기준점은 고정 0.5가 더 낮다 → 실제로는 재현율 목표 기준점이 대부분 더 낮음(평균 0.39, 5조각 중 4개가 0.5 미만)
- 목표는 **평균적으로는** 지켜짐(재현율 평균 0.797 ≈ 0.80, 오경보 평균 0.53 ≈ 0.5) 하지만 조각마다 들쭉날쭉
  - 이유: 테스트 조각의 사기가 약 95건뿐이라 1건 = 재현율 약 1%p. 조각 1은 76건이 필요한데 75건(0.798)으로 1건 차이 미달. 오경보도 예산이 조각당 약 2.8건이라 2건이냐 5건이냐로 갈림
  - 기준점 자체도 조각마다 크게 흔들림(재현율 목표 0.30~0.51, 예산 0.54~0.87) → 경계 근처의 사기·정상 몇 건이 기준점을 좌우
- 고정 0.5가 이번에 그럭저럭 맞은 건 '처리 없음' 모델의 점수 크기가 우연히 맞았기 때문. 2-3처럼 샘플링한 모델이면 0.5는 크게 빗나감 → 정책으로 정하는 게 원칙
- 재현율 목표 vs 0.5: 사기 6건 더 잡는 대가로 오경보 4건 증가
- 실무 시사점: 목표를 '반드시' 지키려면 여유(예: 85%로 정해 80% 보장)를 두거나, 운영 중 기준점을 주기적으로 다시 맞춰야 함

## 2-4 보완 결과: 기준점에 여유 두기 (`scripts/06b_threshold_margin.py`, 그림 `11_threshold_margin.png`)

5겹 × 3회 = 테스트 조각 15개. 실제 목표는 고정(재현율 80%, 오경보 1만 건당 0.5건), 기준점 고를 때만 여유를 둠.

| 정책 | 학습 조각 설정 | 평균 기준점 | 실제 목표 지킴 | 테스트 재현율 평균 | 오경보/1만 건 평균 | 15조각 합계 (잡음 / 놓침 / 오경보) |
|---|---|---|---|---|---|---|
| 재현율 | 80% | 0.296 | 9/15 | 0.806 | 0.88 | 1,144 / 275 / **75** |
| 재현율 | 85% | 0.0095 | **15/15** | 0.850 | 9.16 | 1,206 / 213 / **780** |
| 재현율 | 90% | 0.0002 | 15/15 | 0.900 | 192.1 | 1,277 / 142 / **16,353** |
| 오경보 | 0.5건 | 0.699 | 10/15 | 0.761 | 0.40 | 1,080 / 339 / 34 |
| 오경보 | 0.4건 | 0.790 | 11/15 | 0.747 | 0.35 | 1,060 / 359 / 30 |
| 오경보 | 0.3건 | 0.908 | 13/15 | 0.700 | 0.25 | 993 / **426** / 21 |

- 사용자 예상: 85% 설정 시 12/15 지킴, 오경보 1.5배 → 실제 15/15 지킴, 오경보 **10.4배**(75 → 780). 90%는 218배
- **재현율 쪽은 '절벽'이 있음**: 사기의 약 80~83%까지는 높은 점수로 쉽게 구분되지만, 나머지 사기는 정상 거래와 점수가 섞여 있어 더 잡으려면 기준점을 0.3 → 0.01 → 0.0002로 거의 0까지 내려야 함 → 오경보 폭증 (PR 곡선 `06_pr_curve_tree_model.png`에서 재현율 0.83 이후 정밀도가 급락하는 구간과 같은 현상)
- **오경보 쪽은 완만한 맞교환**: 0.5 → 0.3건으로 여유를 두면 지킨 조각 10 → 13/15, 대가로 놓친 사기 +87건(339 → 426), 줄어든 오경보 13건
- 시사점: 여유의 '값'이 정책마다 다름. 재현율 목표는 80%와 85% 사이를 더 촘촘히(81~84%) 봐야 적정점을 찾을 수 있음(후보 실험, 미진행). 사기 피해액과 오경보 처리 비용이 있으면 비용 기준으로 정하는 게 원칙

## 3-1단계 결과: Isolation Forest (`scripts/07_isolation_forest.py`, 그림 `12_isolation_forest.png`)

| 방법 | PR-AUC 평균 ± 표준편차 | 상위 k건(≈95) 중 사기 평균 | 재현율 80% 맞출 때 오경보(5겹 합) | ROC-AUC(5겹 합) | 학습 시간 |
|---|---|---|---|---|---|
| IF (비지도, 라벨 없이 전부) | 0.139 ± 0.035 | 23.0 | 8,258 | 0.945 | 0.5초 |
| IF (정상만) | 0.110 ± 0.022 | 18.8 | 8,175 | 0.946 | 0.5초 |
| LightGBM (지도) | **0.850 ± 0.013** | **79.2** | **22** | 0.984 | 2.2초 |

- 사용자 예상: IF 비지도 PR-AUC 0.5 이상 → 실제 0.139 / 정상만이 더 나음 → 실제로는 5조각 모두 정상만이 약간 낮음(평균 −0.029)
- 그래도 무작위(0.0017)보다는 약 80배 높음 → 라벨 없이도 신호는 있음. 단 실무에 쓰기엔 오경보가 너무 많음(LightGBM의 약 375배)
- **ROC-AUC의 함정**: IF의 ROC-AUC는 0.945로 좋아 보이지만 PR-AUC는 0.139. 정상이 압도적으로 많으면 ROC-AUC가 후하게 나온다는 1단계의 판단을 다시 확인
- **특이함 ≠ 사기**: IF가 가장 수상하다고 본 상위 473건 중 360건이 정상이고, 그 정상 거래의 금액 중앙값은 **665**(전체 정상 22, 사기 10). 45%가 금액 상위 1%. 고액·희귀 정상 거래를 '이상'으로 잡고, 정작 사기(소액 위주)는 놓침
- IF 상위 473건에서 잡은 사기는 모두 LightGBM도 잡은 것(IF만 잡은 사기 0건) → 이 데이터에서는 지도학습을 보완하지 못함
- 정상만 학습이 약간 낮은 이유는 확실하지 않음(사기 비율 0.17%라 학습 데이터 차이는 미미, 무작위 추출 차이일 가능성). 미확인
